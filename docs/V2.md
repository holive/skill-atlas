# Version 2: goal-first selection and local search

These are historical notes for the initial 2026-10-25 interface. See [the latest maintenance report](maintenance/2026-11-18.md) for current source changes, the architecture scope correction, and the review execution question.

## Behavior

The active interface offers 10 goals, up to two follow-up questions and 35 explained outcomes. It asks for a desired result rather than splitting software from non-software or treating understanding as an exclusive activity.

Each result presents one suggested next skill or reference, why it fits, a concrete next step, material scope, prerequisites and a conditional alternative. Poteto mode results name their playbook. A reference is labeled as a reference; selecting it does not initiate an execution workflow.

The local keyword search covers all 96 catalog entries. Collection filters apply before ranking. Beta/specialized entries and principles are explicit opt-ins. English/Portuguese related terms support common task wording. This is candidate retrieval, not semantic proof, and the page makes that distinction visible.

Uncertain answers remain pending and show nearby possible directions. Back and history edits remove downstream answers. Changing the goal preserves test notes and unfinished comments; clearing the test note is a separate action. Feedback includes the selected skill or None fits, navigation version, scope answers and source/navigation fingerprints. Search feedback is separated from an unrelated previous guided result.

## The user's module-testing case

For `analyze how to test a module in a system without running the system`:

1. Choose **Plan tests or verify behavior**.
2. Choose **Choose a strategy for testing a module**.
3. Distinguish **Isolated tests may run; the whole system must not start** from **Analysis only; do not execute code**.

Both recommend `matt/codebase-design` as a reference for a concrete testability map: public interface, dependency categories, stand-ins, isolated invocation and unverified integrations. The analysis-only result forbids execution and does not claim checks have been verified. `matt/tdd` is an alternative only if writing tests is requested, testing seams are agreed and execution is permitted.

The original English phrase and Portuguese isolation wording both retrieve `matt/codebase-design` first in the curated local search. These are regression expectations informed by sources, not independent evidence of general retrieval accuracy.

## Rule ownership

- `catalog/navigation.json`: interpreted goal-selection policy, primary/conditional recommendations and material scope.
- `catalog/search-terms.json`: interpreted search synonyms and task aliases.
- `tools/navigation-core.js`: one executable resolver and matcher, reused by UI and Node verification.
- `tools/render_page.py` and `tools/page-template.html`: embedding and interaction adapters. They do not own skill behavior.
- `tools/verify_navigation.js`: structural checks, source-backed regressions and search/filter checks.
- `analysis/navigation-lock.json`: binding between the unchanged interpreted catalog and this navigation curation. It guards accidental stale reuse, not semantic truth.

The compiled skill interpretation and original binary-baseline inputs remain unchanged. No upstream skill was installed or executed. The source ownership/citations for the new recommendations are recorded in `analysis/navigation-findings.md`.

## Verification and limits

Offline checks cover all 35 goal outcomes and seven search examples, preserve unknown answers, reject invented answers, validate source IDs/statuses, expose all 96 entries through filters and reproduce the HTML deterministically. The original 22 binary scenarios remain baseline regressions.

Browser checks cover all 35 outcomes and expected primary cards, the exact module-isolation phrase, the analysis-only variant, collection and lifecycle filters, no-match behavior, uncertain questions, changing an answer, note preservation and feedback saving. No browser console errors were observed. The JSON download mechanism is retained from version 1; its download was not repeated in this browser run.

Real-user selection success on held-out tasks has not been measured. The current update tests a plausible improvement to navigation and discovery; it does not certify that every recommendation is optimal, that every skill works on the current host, or that a local unit check establishes full-system behavior.
